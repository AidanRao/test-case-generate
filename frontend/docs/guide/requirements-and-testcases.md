# 需求与测试用例

进入项目后，可以围绕需求完成测试设计、用例维护、覆盖分析和报告导出。

## 浏览模块与需求

项目需求按功能模块组织。选择模块后，可以查看该模块下的需求列表和需求详情。

需求详情支持 Markdown 内容，因此标题、列表、代码块、表格和数学公式等内容能够保持清晰排版。

## 生成测试用例

可以针对单条需求发起测试用例生成。系统会创建后台任务，并在生成期间展示当前状态。

为了获得更稳定的结果，建议需求至少包含：

- 明确的业务目标。
- 输入条件和约束。
- 正常流程。
- 异常处理规则。
- 可以验证的输出或状态变化。

## 编辑测试用例

打开用例详情后，可以查看并调整用例名称、类型、场景、优先级、测试目标、验证方法和测试步骤。

每个测试步骤应分别描述操作和预期结果，避免把多个独立验证点合并到同一步中。

## 覆盖分析

覆盖分析用于识别尚未关联测试用例的需求。计算完成后，可以查看项目整体覆盖情况和每条需求的覆盖状态。

::: info
当前覆盖状态根据需求是否至少关联一条测试用例判断。覆盖结果适合定位空白需求，不替代人工的场景完整性评审。
:::

## 导出测试用例

项目测试用例支持导出为多种格式：

| 格式 | 适用场景 |
| --- | --- |
| Word | 评审、归档和正式交付 |
| Excel | 批量筛选、整理和执行记录 |
| Markdown | 轻量阅读和版本管理 |
| JSON | 数据交换和二次处理 |

导出 Word 时，可以在导出面板中选择系统提供的报告模板。
