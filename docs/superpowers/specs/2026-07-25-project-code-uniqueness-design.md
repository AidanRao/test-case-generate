# 前端项目编号重复校验设计

## 背景

当前新建和编辑项目时，`ProjectDialog` 只校验项目名称与项目编号是否为空，没有校验编号是否已被其他项目使用。虽然后端接口会拒绝完全相同的编号，但前端不能在提交前给出字段级提示，而且新建流程可能把接口失败降级为本地项目，导致重复编号继续进入前端项目列表。

## 目标

- 新建项目时，项目编号不能与任何现有项目重复。
- 编辑项目时，项目可以保留自己的原编号，但不能改成其他项目的编号。
- 编号比较前去除首尾空格并忽略大小写；例如 `PRJ-001`、` prj-001 ` 视为同一编号。
- 重复时在项目编号输入框下显示“项目编号已存在”，并阻止进入下一步或保存。
- 保留后端现有的重复编号保护，不新增校验接口。

## 设计

### 数据流

`Projects.vue` 根据当前项目列表计算已占用编号，并将其传给 `ProjectDialog`：

- 新建模式传入全部项目编号。
- 编辑模式排除当前编辑项目后，再传入其余项目编号。

`ProjectDialog` 负责字段级校验。校验函数对输入编号和已占用编号执行相同的标准化：先 `trim()`，再转换为小写。标准化后的编号相同即判定重复。

### 交互

- 用户点击新建流程的“下一步”或最终“创建”时执行校验。
- 用户点击编辑弹窗的“保存”时执行校验。
- 编号为空时仍显示现有的“请输入项目编号”。
- 编号重复时显示“项目编号已存在”。
- 校验失败时不触发 `submit`，弹窗保持打开。
- 用户修改编号后再次提交时重新计算并更新错误提示。

### 边界

- 本次仅增加前端校验，不修改后端重复校验规则或新增接口。
- 不校验项目名称是否重复。
- 不改变 UniPortal 只读项目的编辑行为。
- 不重构项目创建失败后的本地降级策略。

## 测试

新增独立、可测试的项目编号标准化与重复判断函数，并覆盖：

1. 新建项目使用已有编号时判定重复。
2. 编号比较忽略首尾空格和大小写。
3. 编辑项目保留自身原编号时不判定重复。
4. 编辑项目改成其他项目编号时判定重复。

同时运行前端类型检查和生产构建，确认 Vue 模板及属性传递正确。
