# 默认 Word 测试用例模板设计

## 目标

替换现有 `default` Word 导出模板，使导出的测试用例文档固定包含以下三个一级章节：

1. 文档概述
2. 需求与用例概述
3. 需求与测试用例明细

本次替换后端默认 Word 内容结构，并增加后端模板目录接口和前端
Word 模板选择交互。不保留旧 Word 内容结构的兼容逻辑。

## 总体方案

采用“Word 外壳模板 + 面向对象章节渲染器”。

`.docx` 模板负责封面、分节、页眉、页脚和基础版式。Python 代码负责构建报告上下文、统计数据并渲染正文。`WordReportRenderer` 只负责编排章节，三个一级章节分别由独立的章节渲染器生成。标题、表格、字体、单元格合并等通用 Word 操作由可复用的文档组件封装。

`backend/template/test_case_report-v2.docx` 作为新默认模板的基础。模板注册表中的 `default` 直接指向新模板，旧模板不再参与 Word 导出。

模板注册表是模板编码、显示名称和实际文件之间的唯一映射来源。
前端通过后端目录接口获得模板编码和显示名称，不在前端重复维护模板
路径或映射。

## 数据来源与默认值

报告数据继续由项目、需求和测试用例三类现有存储记录构建。

### 项目信息

- 文档名称：`{项目名称}测试用例文档`
- 项目名称：项目的 `title`
- 文档版本：固定为 `V1.0`
- 编制日期：执行导出的当天日期，格式为 `YYYY-MM-DD`

封面标题和 Word 核心属性中的文档标题均使用文档名称，即
`{项目名称}测试用例文档`。

### 需求信息

- 模块：需求的 `module`；空值显示为“未命名模块”
- 需求编号：需求的 `code`
- 需求名称：需求的 `title`
- 需求类型：需求的 `type`；空值显示为“未知类型”
- 需求内容：需求的 `content`；空值显示为“暂无”

### 测试用例信息

- 用例编号：测试用例的 `code`
- 用例名称：测试用例的 `title`
- 用例类型：测试用例的 `type`；空值显示为“未知类型”
- 场景类型：测试用例的 `scenario_type`；空值显示为“暂无”
- 优先级：测试用例的 `priority`；空值使用项目既有默认值 `P1`
- 测试目标、验证方法及测试步骤沿用现有字段；空值显示为“暂无”

需求和测试用例保持存储层返回的原始顺序。同一模块下的需求连续排列。

## 报告上下文

报告上下文由专用构建器一次性计算，渲染器不再执行分组或统计等业务规则。上下文包含：

- 项目元数据
- 按模块分组的需求及其关联测试用例
- 需求统计行
- 按用例类型聚合的统计行
- 按用例优先级聚合的统计行
- 需求覆盖分析行
- 总需求数和总用例数

用例类型和优先级统计的占比按 `该分类用例数量 / 总用例数量` 计算，显示为百分比并保留两位小数。总用例数为零时，占比显示为 `0.00%`。

覆盖状态只有两种：

- 需求下存在至少一条关联测试用例：`已覆盖`
- 需求下没有关联测试用例：`未覆盖`

不生成“部分覆盖”状态。

## 第一章：文档概述

一级标题为 `一、文档概述`。

正文使用两列表格，第一列为字段名，第二列为字段值，依次展示：

| 字段 | 值 |
| --- | --- |
| 文档名称 | `{项目名称}测试用例文档` |
| 项目名称 | 项目标题 |
| 文档版本 | `V1.0` |
| 编制日期 | 导出当天日期 |

## 第二章：需求与用例概述

一级标题为 `二、需求与用例概述`。

### 需求统计

二级标题为 `需求统计`。

统计表包含以下五列：

| 模块 | 需求编号 | 需求名称 | 需求类型 | 用例数量 |
| --- | --- | --- | --- | ---: |

需求按模块分组展示。同一模块对应的相邻数据行中，“模块”列纵向合并为一个单元格。只有一个需求的模块不执行多行合并。

### 用例统计

二级标题为 `用例统计`。

该部分包含两个三级标题和两张表：

1. `按用例类型统计`
   - 列：用例类型、用例数量、占比
2. `按优先级统计`
   - 列：优先级、用例数量、占比

分类按照第一次出现在项目用例数据中的顺序展示。没有任何测试用例时，两张表均保留表头，并增加一行“暂无数据”。

### 需求覆盖分析

二级标题为 `需求覆盖分析`。

统计表包含以下五列：

| 需求编号 | 需求名称 | 关联用例 | 用例数量 | 覆盖状态 |
| --- | --- | --- | ---: | --- |

“关联用例”展示需求下全部测试用例编号，并使用中文顿号 `、` 分隔。没有关联用例时显示“暂无”，用例数量为 `0`，覆盖状态为“未覆盖”。

## 第三章：需求与测试用例明细

一级标题为 `三、需求与测试用例明细`。

内容按以下层级组织：

- 模块：二级标题，文本为 `模块：{模块名称}`
- 需求：三级标题，文本为 `需求：{需求名称}`
- 测试用例：四级标题，文本为 `{序号}. {用例名称}`

每个需求标题下展示需求编号、需求类型和需求内容。

每个测试用例标题下展示：

- 编号
- 类型
- 场景
- 优先级
- 测试目标
- 验证方法
- 测试步骤

测试步骤继续使用“序号、测试步骤、预期结果”三列表格。需求没有测试用例时显示“测试用例：暂无”；测试用例没有步骤时显示“测试步骤：暂无”。

## 组件边界

### 报告上下文构建器

负责规范化原始数据、建立需求与测试用例关联、按模块分组，并计算全部统计和覆盖数据。该组件不依赖 Word。

### Word 报告渲染器

负责加载默认模板、准备正文锚点、按顺序调用章节渲染器、启用 Word 字段更新并保存文档。该组件不计算业务统计。

### 章节渲染器

每个一级章节由一个独立对象负责：

- 文档概述章节
- 需求与用例概述章节
- 需求与测试用例明细章节

所有章节通过统一接口接收 Word 文档、正文锚点和报告上下文。

### Word 文档组件

封装标题、元数据段落、通用表格、步骤表格、字体、边框、列宽、表头重复、禁止跨页断行和纵向合并等操作。章节渲染器只描述内容，不直接操作底层 XML，只有文档组件可以封装必要的 `python-docx` XML 操作。

所有由该组件生成的 Word 表格统一使用五号字，即 `10.5 pt`。表头和
正文单元格均直接设置该字号，因此当前和以后注册的模板自动使用相同
表格字号。表格外的正文和标题继续使用既有字号层级。

## Word 模板注册与目录接口

后端使用一个有序、便于修改的代码内注册表集中维护模板。每个模板
定义包含：

- `template_id`：模板编码
- `name`：前端显示名称
- `filename`：相对于后端模板目录的文件名
- `title_marker`：封面标题标记
- `body_anchor_strategy`：正文锚点策略

当前唯一模板定义为：

```python
"default": {
    "name": "标准测试用例文档",
    "filename": "test_case_report.docx",
    "title_marker": "xx测试报告",
    "body_anchor_strategy": "last_body_paragraph",
}
```

新增接口：

```http
GET /v1/testcase-report-templates
```

成功响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "template_id": "default",
        "name": "标准测试用例文档"
      }
    ]
  }
}
```

接口只返回注册表中定义且对应模板文件实际存在的项目，并保持注册表
顺序。响应不包含服务器文件路径、标题标记或锚点策略。模板文件缺失
属于部署配置问题：该模板不出现在前端目录中，直接使用其编码导出时
仍由现有 Word 渲染错误处理负责。

## 前端模板选择

现有导出弹窗保留 JSON、Markdown、Word、Excel 四种格式。

选择 Word 后，Word 选项卡向下展开，并在内部显示后端返回的模板名称
单选列表。当前列表仅显示“标准测试用例文档”，不显示模板编码、实际
路径或描述。

交互规则：

- 打开弹窗时将格式重置为 JSON。
- 首次打开弹窗时请求模板目录；成功结果在当前页面生命周期内缓存。
- 模板目录按接口顺序展示，默认选择第一项。
- 在不同导出格式之间切换时保留本次已选模板。
- 加载中显示“正在加载模板”。
- 空列表显示“暂无可用模板”。
- 加载失败显示内联错误；再次打开弹窗时重试。
- Word 未选择有效模板时不触发导出，其他格式继续正常导出。

导出事件使用对象传递选择结果：

```typescript
type ExportSelection = {
  format: ExportFormat
  templateId?: string
}
```

Word 导出把 `templateId` 传给现有
`exportTestcasesWord(projectId, templateId)`，最终仍使用现有
`template_id` 查询参数。

## 错误处理

- `template_id` 不在注册表白名单内时，继续返回现有参数错误。
- 默认 Word 模板文件不存在时，返回现有 Word 导出失败错误。
- 封面标题标记或正文锚点缺失时，抛出明确的报告渲染异常，并由导出接口转换为现有统一错误响应。
- 空需求、空用例和空步骤属于合法业务状态，在文档中展示明确的空值提示，不视为渲染错误。

## 测试策略

采用测试驱动开发。

### 上下文单元测试

覆盖：

- 文档元数据和导出日期
- 模块、需求和用例的分组与原始顺序
- 需求用例数量
- 用例类型统计
- 优先级统计及缺省 `P1`
- 百分比计算和零用例场景
- 关联用例编号
- “已覆盖”和“未覆盖”状态
- 空字段显示值

### Word 渲染测试

生成 `.docx` 后使用 `python-docx` 重新读取并验证：

- 三个一级标题的存在和顺序
- 模块、需求、测试用例分别使用二、三、四级标题
- 文档概述表内容
- 需求统计表内容与模块单元格纵向合并
- 两张用例统计表的分类、数量和占比
- 需求覆盖分析表的关联编号、数量和覆盖状态
- 需求与用例明细及步骤表
- 中英文字体、表格几何、重复表头、禁止跨页断行、页脚页码和分节
- 默认模板注册和非法模板标识拒绝
- 每张生成表格的表头和正文单元格均为 `10.5 pt`

### 模板目录接口测试

覆盖：

- 注册表中的模板编码、显示名称和文件名映射
- 目录接口返回模板编码与名称
- 目录接口不暴露服务器文件路径
- 模板文件缺失时从可选目录中过滤
- 列表顺序与注册表顺序一致

### 前端测试与构建

覆盖：

- 接口响应到前端模板选项的数据类型
- 首项默认选择
- Word 导出携带所选模板编码
- 非 Word 导出不依赖模板选择
- 模板加载、空列表和失败状态的组件分支通过 Vue/TypeScript 构建

### 回归验证

- 运行 Word 导出测试
- 运行 Excel 导出回归测试
- 运行后端完整测试集
- 运行前端模板选择逻辑测试
- 运行前端 TypeScript/Vue 生产构建
- 渲染代表性多页 Word，并逐页检查标题、表格、合并单元格、分页和页码

## 不在本次范围

- 用户自定义文档版本
- 用户自定义编制日期
- “部分覆盖”状态
- 旧 Word 正文结构兼容
- PDF 导出
- 模板描述、预览图和用户上传模板
- 在前端暴露模板实际文件路径
